# T2.3 · Subida idempotente y consulta de escaneos

**Fase:** 2 · **Quién:** 🤖 Sonnet · **Depende de:** T1.8, T2.2 · **Tamaño:** M
**Rama:** `t2-3-escaneos-api`

## Objetivo

Endpoints que usa la pantalla Escanear: subir una foto, consultar su resultado y obtener URLs firmadas de imagen y miniatura.

## Contexto (leer)

- `docs/especificacion.md` §5 (en el celular: subida idempotente y consulta cada 1,5 s), §11 (`POST /companies/:id/scans`, `GET /scans/:id`, `/image`, `/thumb`, notas), §9.3 (qué necesita la app para las alertas).
- `docs/plan/README.md` §4, decisión 8 (`replaces_scan_id`).

## Qué hacer

1. `POST /companies/:id/scans` (miembro), `multipart/form-data` con **multer** en memoria:
   - Campos: `image` (JPEG, máximo **5 MB**, 413 si se pasa), `client_id` (UUID), `captured_at` (ISO), `lat`, `lng` (opcionales), `replaces_scan_id` (opcional, debe ser de la misma empresa).
   - Llamar a `createScan` (T1.8). Respuesta `201` con `{ scan_id, status }`; si el `client_id` ya existía, `200` con el escaneo existente (sin reprocesar ni cobrar de nuevo).
2. `GET /scans/:id` (miembro de la empresa del escaneo): DTO para la app:
   ```json
   { "id", "status", "doc_type", "conformidad_nivel", "cliente_nombre", "local", "serie", "numero",
     "fecha_documento", "total", "revisar": [...], "fields": { "<clave>": { "value", "corrected": bool } },
     "captured_at", "thumb_url", "alert": "sin_firma" | "no_reconocido" | "revisar" | "error" | null }
   ```
   - `fields` con la regla de lectura de §10 (corrección si existe) y solo las claves de `fields_requested` + las del QR.
   - `alert` según §9.3: `sin_firma` si `conformidad_nivel` es `sin_firma` o `dudosa`; `no_reconocido` si el tipo es ese; `revisar` si hay `revisar`; `error` si el estado es error.
   - **Nunca** incluir `ai_cost_usd`, tokens ni modelo (§11: el costo no se muestra a clientes).
3. `GET /scans/:id/image` y `GET /scans/:id/thumb`: devuelven `{ url, expires_at }` con `signImageUrl` (5 minutos).
4. Serializador único `toScanDto(scan)` en `server/src/scans/dto.ts` para reutilizar en T2.4.

## Criterios de aceptación (tests con PGlite, LocalStore y IA falsa)

- Subida → `GET /scans/:id` pasa de `procesando` a `listo` con la tarjeta completa.
- Repetir la subida con el mismo `client_id` devuelve el mismo `scan_id` y no se procesa de nuevo.
- Imagen de más de 5 MB → 413; usuario de otra empresa → 404.
- El DTO no expone costo, tokens ni modelo.
- La URL firmada devuelta sirve la imagen (usar la ruta de T1.5).

## Fuera de alcance

Listado y filtros (T2.4).
