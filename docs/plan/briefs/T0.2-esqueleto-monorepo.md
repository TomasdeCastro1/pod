# T0.2 · Esqueleto del monorepo, CLAUDE.md y CI

**Fase:** 0 · **Quién:** 🤖 Sonnet · **Depende de:** T0.1 · **Tamaño:** M
**Rama:** `t0-2-esqueleto`

## Objetivo

Dejar el repositorio listo para que cada tarea siguiente solo agregue código: estructura de carpetas, TypeScript, lint, tests, CI y un `CLAUDE.md` con las convenciones que todas las sesiones van a seguir.

## Contexto

- La especificación completa está en la carpeta del plan como `especificacion.md`. Si no la tenés en el repo, Francisco te la pasa junto con la carpeta `plan/`.
- Stack: sección 3 de la especificación.

## Qué hacer

1. Copiar la especificación a `docs/especificacion.md` y la carpeta del plan a `docs/plan/` (README + briefs).
2. Crear un monorepo con **npm workspaces**:
   ```
   server/    Backend Node.js + TypeScript + Express
   mobile/    App Expo (solo un placeholder en esta tarea; T3.1 la crea)
   shared/    Código TypeScript usado por server y mobile (tipos, claves de campos, RUT, precio)
   samples/   Fotos de prueba (ya subidas por Francisco) + expected.json (lo crea T1.9)
   docs/
   ```
3. `server/` y `shared/`: TypeScript estricto, Node 20+, ESM, **Vitest** para tests, **ESLint** + **Prettier**. Scripts en la raíz: `npm run lint`, `npm run typecheck`, `npm test`, `npm run format`.
4. `shared/` exporta desde `shared/src/index.ts` y se consume como paquete del workspace (`@app/shared`).
5. `.env.example` en `server/` con todas las variables (sin valores): `DATABASE_URL`, `ANTHROPIC_API_KEY`, `JWT_SECRET`, `RESEND_API_KEY`, `ADMIN_TOKEN`, `SIGNED_URL_SECRET`, `MODEL_PRIMARY`, `MODEL_SECONDARY`, `ROUTE_PAPER_RETURNS_TO_SECONDARY`, `STORAGE_DRIVER` (`replit` | `local`), `LOCAL_STORAGE_DIR`, `PUBLIC_BASE_URL`, `REVIEW_EMAIL`, `REVIEW_CODE`, `EMAIL_DRIVER` (`resend` | `console`).
6. GitHub Actions `.github/workflows/ci.yml`: en cada PR, `npm ci`, lint, typecheck y tests. Sin secretos: los tests que llaman a la API de Anthropic no corren en CI.
7. `.gitignore` adecuado (node_modules, .env, builds de Expo, carpeta de almacenamiento local).
8. `CLAUDE.md` en la raíz con:
   - Qué es el proyecto en dos líneas y dónde están la especificación y el plan.
   - Estructura del monorepo.
   - Comandos para lint, typecheck, tests y `test:samples`.
   - Convenciones: código y nombres de variables en inglés salvo las claves de negocio de la especificación (`conformidad_nivel`, `cliente_rut`, etc.), que se usan tal cual; textos de la app en español rioplatense como en la especificación; validación con zod en todos los bordes; nada de secretos en el código.
   - Regla de trabajo: una tarea por PR, siguiendo su brief en `docs/plan/briefs/`; correr lint, typecheck y tests antes de abrir el PR.
9. `README.md` corto para humanos: qué es y cómo arrancar en local.

## Entregables

PR con la estructura, CI verde y `CLAUDE.md`.

## Criterios de aceptación

- `npm ci && npm run lint && npm run typecheck && npm test` pasa en limpio en la raíz (con al menos un test trivial en `shared`).
- CI corre en el PR y queda verde.
- `docs/especificacion.md` y `docs/plan/` están en el repo.

## Fuera de alcance

Base de datos, Express, Expo real. Solo esqueleto.
