# T2.6 · Deploy de staging en Replit

**Fase:** 2 · **Quién:** 🤖 Sonnet prepara · 👤 Francisco ejecuta en Replit · **Depende de:** T2.3 · **Tamaño:** S
**Rama:** `t2-6-deploy`

## Objetivo

Tener el backend corriendo en Replit con PostgreSQL y Object Storage, para que la app de desarrollo (T3.4) tenga contra qué hablar.

## Contexto (leer)

- `docs/especificacion.md` §3 (secrets), §13.2.
- `docs/plan/README.md` §4, decisiones 1 y 2.

## Qué hace Sonnet

1. Archivos de configuración de Replit en la raíz: `.replit` y `replit.nix` (o la configuración equivalente actual de Replit; consultar https://docs.replit.com) con:
   - build: `npm ci && npm run build -w server && npm run db:migrate -w server && npm run db:seed -w server`
   - run: `node server/dist/index.js`
   - puerto desde `PORT`.
2. Script `npm run build -w server` que compila a `server/dist`.
3. `STORAGE_DRIVER=replit` usa `ReplitStore` (T1.5); verificar que `@replit/object-storage` toma el bucket por defecto.
4. `docs/deploy.md` con los pasos exactos para Francisco (abajo), la lista de secrets y cómo verificar que funciona (`/health`, pedir un código de login).

## Qué hace Francisco (pasos que van en `docs/deploy.md`)

1. En Replit: «Import from GitHub» con el repositorio.
2. Agregar la base PostgreSQL de Replit y un bucket de Object Storage al Repl.
3. Cargar los Secrets: `ANTHROPIC_API_KEY`, `DATABASE_URL` (lo pone Replit), `JWT_SECRET`, `RESEND_API_KEY`, `ADMIN_TOKEN`, `SIGNED_URL_SECRET`, `PUBLIC_BASE_URL`, `STORAGE_DRIVER=replit`, `EMAIL_DRIVER=resend`, `REVIEW_EMAIL`, `REVIEW_CODE`.
4. Publicar como **Reserved VM** (no Autoscale: el procesamiento en segundo plano necesita el proceso vivo).
5. Probar `https://<dominio>/health` y pasar la URL a la sesión de T3.x.

## Criterios de aceptación

- `/health` responde en la URL pública.
- Un login real llega al email y entrega token.
- Un `POST /companies/:id/scans` con `samples/06.jpg` termina `listo` en el servidor de staging.

## Fuera de alcance

Dominio propio y backups (T6.3).
