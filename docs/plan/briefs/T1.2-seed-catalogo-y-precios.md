# T1.2 · Seed del catálogo de campos, precios y modelos

**Fase:** 1 · **Quién:** 🤖 Sonnet · **Depende de:** T1.1 · **Tamaño:** M
**Rama:** `t1-2-seed`

## Objetivo

Cargar `field_catalog`, `price_settings` y `model_prices` con los datos de la especificación, de forma idempotente, y exponer funciones para leer el catálogo y calcular el precio de una empresa.

## Contexto (leer)

- `docs/especificacion.md` §7 (catálogo, 7.1 y 7.2), §9.4 (modelos), §10 (tablas), §12 (fórmula de precio).
- `docs/plan/README.md` §4, decisiones 5, 6 y 9.

## Qué hacer

1. `server/src/db/seed/fieldCatalog.ts`: un arreglo tipado con **todos** los campos de §7.1 (15 base) y §7.2 (27 opcionales), con:
   - `key`, `label`, `group` (para base usar `"Incluido"`), `doc_types` (`factura` | `devolucion`; «Todos» = ambos; «Solo CFE» = ambos pero `source='qr'`), `is_base`, `source` (`qr_o_ia`, `ia`; agregar el valor `qr` para `tipo_cfe`), `instruction` (copiada literal de la columna «Instrucción para la IA»), `is_item_field` (true para `items[]` y los `fact_item_*`, `dev_item_*`), `price_per_1000_usd` (0 para base), `sort_order` (orden de la especificación), `active=true`.
   - `est_in_tokens` y `est_out_tokens` según la decisión 5 del plan: `est_in = ceil(len("- clave: instrucción") / 4)`; `est_out = max(3, round((costo_ia × 1000 − est_in) / 5))`. Para campos base usar `est_out` 10 (20 para `sello_texto` y `notas_manuscritas`, 60 para `items`). Dejar la fórmula en un comentario.
   - `items[]` base: clave `items`, con subcampos `codigo`, `descripcion`, `cantidad`, solo `devolucion`.
2. `price_settings`: una fila, base 40 USD.
3. `model_prices`: `claude-haiku-4-5-20251001` 1,00 / 5,00 y el modelo de `MODEL_SECONDARY` (por defecto `claude-sonnet-5-5`). **No inventes precios:** buscá el precio vigente en la documentación oficial de Anthropic (https://docs.anthropic.com, página de precios); si no podés verificarlo, cargá 3,00 / 15,00 y dejá un `TODO` visible en el PR.
4. Script `npm run db:seed` idempotente (upsert por clave; correrlo dos veces no duplica ni pisa precios ya editados — usar `on conflict do nothing` para precios y `do update` solo para `instruction`, `label` y estimaciones).
5. `server/src/catalog.ts`:
   - `getCatalog(db)`: catálogo activo ordenado.
   - `getCompanyFields(db, companyId)`: base + opcionales con `enabled`.
   - `getRequestedFields(db, companyId, docType | null)`: claves que se piden para ese tipo (sin filtrar por QR; eso lo hace T1.6).
   - `computePricePer1000(db, companyId)`: base + suma de opcionales activos (usar la función pura de `shared` de T1.3 si ya existe; si no, crearla en `shared/src/pricing.ts`).

## Criterios de aceptación

- Test: con todos los opcionales activos, el precio es **76**; sin ninguno, **40**; con `fecha_vencimiento`, `orden_compra` y `dev_plazo_retiro_dias` es **45** (ejemplo de §12).
- Test: el catálogo tiene 15 campos base y 27 opcionales, y la suma de precios opcionales es 36.
- Test: correr el seed dos veces deja la misma cantidad de filas.

## Fuera de alcance

Endpoints (T2.5), construcción del prompt (T1.6).
