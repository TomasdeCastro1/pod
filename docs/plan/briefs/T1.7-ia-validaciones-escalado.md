# T1.7 · Llamada a la IA, validaciones, escalado y costo

**Fase:** 1 · **Quién:** 🤖 Sonnet · **Depende de:** T1.3, T1.6 · **Tamaño:** L
**Rama:** `t1-7-ia`

## Objetivo

Dada la copia de la imagen y el prompt, obtener un resultado validado: llamar al modelo primario, validar, reintentar o escalar una sola vez al secundario, combinar con el QR y calcular tokens y costo real.

## Contexto (leer)

- `docs/especificacion.md` §8.3, §8.4, §9 completa (9.1 a 9.4), §5 (último paso).
- Usar el SDK oficial `@anthropic-ai/sdk`. Para dudas del SDK o de los modelos, consultar https://docs.anthropic.com.

## Qué hacer

1. `server/src/ai/client.ts`: `callModel({ model, system, imageJpeg, userText, maxTokens })` → `{ text, inputTokens, outputTokens, model }`. Mensaje de usuario: bloque `image` (base64, `image/jpeg`) y después bloque `text`. `temperature: 0`. **Sin tool use y sin prompt caching** (§8.4). Inyectable para tests (pasar el cliente por parámetro y usar un fake en tests).
2. `server/src/ai/parse.ts`: extraer el JSON de la respuesta (tolerar que venga envuelto en ```json por error); esquema **zod dinámico** armado con `requestedKeys` e `itemKeys` (valores string/number/boolean opcionales; `items` array de objetos; `revisar` array de `{campo, motivo}`; `conformidad_nivel` y `tipo_documento` como enums). Claves extra: descartarlas y anotarlas en un log de depuración.
3. `server/src/ai/validate.ts`: `validate(result, { qrData, companyRut, preclassified, requestedKeys })` → `{ result, issues: {campo, motivo}[], mustEscalate: boolean }` con las reglas de §9.1:
   - RUT: todo RUT leído (`rut_emisor`, `cliente_rut`) pasa `isValidRut`; si no → issue + escalar.
   - QR contra imagen: si la IA leyó un dato que vino en el QR y no coincide, gana el QR y se agrega a `revisar`.
   - Tipo contra QR: si el QR dice que el emisor es la empresa, se fuerza factura/nota de crédito.
   - Aritmética: solo si están todos los importes de línea, descuento, subtotal, IVA y total: Σ importes − descuento = subtotal y subtotal + IVA = total, con ±0,05; si no cierra → `revisar` (no escala).
   - Cantidades positivas.
   - Normalizar números con `parseUyNumber` si vinieron como string y fechas a `AAAA-MM-DD`.
4. `server/src/ai/extract.ts`: orquesta según §9.2:
   1. Llamar a `MODEL_PRIMARY`. Si el JSON no parsea, reintentar una vez con el mismo modelo.
   2. Escalar **una vez** a `MODEL_SECONDARY` si: JSON inválido tras el reintento; algún RUT inválido; `revisar` no vacío; `conformidad_nivel = dudosa`; o devolución sin QR de DGI con `ROUTE_PAPER_RETURNS_TO_SECONDARY=true` (en ese caso ir directo al secundario).
   3. Resultado final = el del secundario si se escaló (validado de nuevo); si sigue dudoso → estado `revisar`.
   4. Estado: `error` si nunca hubo JSON válido; `revisar` si `revisar` quedó no vacío; `listo` en cualquier otro caso. Un documento `no_reconocido` queda `listo` con ese tipo: la app lo muestra como «No se pudo leer el comprobante» (§9.3).
   5. Devolver `{ status, docType, extracted, modelUsed, escalated, inputTokens, outputTokens, aiCostUsd, calls: [...] }`, sumando tokens de **todas** las llamadas.
5. `server/src/ai/cost.ts`: `costUsd(model, inTok, outTok, modelPrices)` con `model_prices` (USD por millón).
6. Combinar QR + IA: los datos del QR se copian a `extracted` y tienen prioridad.

## Criterios de aceptación (tests con cliente falso, sin red)

- JSON válido y limpio → una llamada, `listo`.
- JSON roto y luego válido → dos llamadas al primario, sin escalar.
- RUT inválido → escala; el secundario corrige → `listo`, `escalated=true`, tokens sumados de las dos llamadas.
- `conformidad_nivel = dudosa` → escala; el secundario también dice `dudosa` → queda `listo` con `dudosa` (la alerta la decide la app) y `escalated=true`.
- Discrepancia QR/IA en número → gana el QR, aparece en `revisar`, estado `revisar` si tras escalar sigue.
- Aritmética que no cierra → `revisar` sin escalar por ese motivo solo.
- `ROUTE_PAPER_RETURNS_TO_SECONDARY=true` y devolución sin QR → única llamada al secundario.
- Costo calculado coincide con la fórmula para un caso conocido.

Agregar además un test de integración **opcional** que llama de verdad a la API con `samples/06.jpg` y se salta si no hay `ANTHROPIC_API_KEY`.
