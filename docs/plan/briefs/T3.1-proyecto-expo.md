# T3.1 · Proyecto Expo, pestañas, cliente de API y configuración EAS

**Fase:** 3 · **Quién:** 🤖 Sonnet · **Depende de:** T0.2 · **Tamaño:** M
**Rama:** `t3-1-expo`

## Objetivo

Crear la app en `mobile/` con Expo + TypeScript + Expo Router, tres pestañas vacías, cliente de API tipado y configuración para development builds de EAS desde el primer día.

## Contexto (leer)

- `docs/especificacion.md` §3 (tabla de librerías de la app y nota sobre Expo Go), §4 (estructura de pestañas), §13.1 (identificador, textos de permisos).
- Identificador de la app: el que decidió Francisco en T0.1. Si no está en `CLAUDE.md`, usar `uy.puntosano.comprobantes` como marcador y señalarlo en el PR.

## Qué hacer

1. `npx create-expo-app mobile --template` (TypeScript, SDK estable más reciente) dentro del workspace; ajustar Metro para el monorepo y consumir `@app/shared`.
2. Expo Router con `app/(tabs)/_layout.tsx` y tres pestañas: **Escanear** (ruta inicial), **Archivo**, **Perfil**, con íconos y textos en español. Grupo `app/(auth)/` para login y onboarding (pantallas vacías por ahora).
3. Encabezado común con el nombre de la empresa activa (placeholder) que al tocarlo abrirá el selector (T5.1).
4. Instalar las librerías de §3 que van a usar las siguientes tareas: `react-native-document-scanner-plugin`, `expo-image-manipulator`, `expo-file-system`, `expo-sqlite`, `@react-native-community/netinfo`, `expo-location`, `expo-haptics`, `expo-sharing`, `expo-secure-store`, `expo-dev-client`, y `@tanstack/react-query` para el manejo de datos.
5. `app.config.ts`:
   - `ios.bundleIdentifier` y `android.package` con el identificador.
   - Textos de permisos en español exactamente como §13.1 (cámara y ubicación).
   - Plugin del escáner configurado según su README.
   - `extra.apiBaseUrl` desde `EXPO_PUBLIC_API_URL`.
6. `eas.json` con perfiles `development` (dev client, distribución interna), `preview` y `production`.
7. `mobile/src/api/client.ts`: wrapper de `fetch` con base URL, JWT desde `expo-secure-store`, manejo de 401 (cerrar sesión), errores tipados, y funciones tipadas para los endpoints de §11 (tipos en `shared/src/api.ts` para compartir con el servidor). Subida multipart con `FormData`.
8. Tema visual simple: colores de conformidad (verde, amarillo, naranja, rojo) como constantes en `shared` para que Archivo y Escanear usen los mismos.
9. Lint y typecheck de `mobile` incluidos en el CI.

## Criterios de aceptación

- `npx expo-doctor` sin errores; `npm run typecheck` y lint pasan en `mobile`.
- `npx expo export` (o `expo prebuild --no-install` en seco) termina sin errores, como prueba de que la configuración compila. No se puede probar en un celular desde la sesión: eso es T3.4.

## Fuera de alcance

Lógica de login, escáner y pantallas reales.
