# T1.1 · Servidor base y esquema de base de datos

**Fase:** 1 · **Quién:** 🤖 Sonnet · **Depende de:** T0.2 · **Tamaño:** M
**Rama:** `t1-1-servidor-esquema`

## Objetivo

Servidor Express que arranca, carga configuración validada y tiene el esquema completo de PostgreSQL con Drizzle y sus migraciones.

## Contexto (leer)

- `docs/especificacion.md` §3 (stack), §10 (modelo de datos), §13.2 (seguridad).
- `docs/plan/README.md` §4, decisiones 2, 4 y 8.

## Qué hacer

1. `server/src/config.ts`: lee variables de entorno con zod; falla al arrancar si falta alguna obligatoria. Valores por defecto: `MODEL_PRIMARY=claude-haiku-4-5-20251001`, `MODEL_SECONDARY=claude-sonnet-5-5`, `ROUTE_PAPER_RETURNS_TO_SECONDARY=false`, `STORAGE_DRIVER=local`, `EMAIL_DRIVER=console`.
2. `server/src/app.ts` (crea la app Express, sin `listen`, para poder testear con supertest) y `server/src/index.ts` (arranca). Middlewares: JSON, manejo central de errores con respuesta `{ error: { code, message } }`, `GET /health`.
3. Drizzle ORM con driver `pg` (node-postgres). Esquema en `server/src/db/schema.ts` con las **10 tablas** de §10, exactamente con esas columnas, más:
   - `scans.replaces_scan_id` (nullable, referencia a `scans.id`) — decisión 8 del plan.
   - Tipos: ids `uuid` con `defaultRandom()`; importes `numeric(12,2)`; precios `numeric(10,4)`; `extracted`, `corrections`, `qr_data`, `detail` en `jsonb`; `doc_types` y `fields_requested` como `text[]`; enums de Postgres para `role`, `status`, `conformidad_nivel`, `source`.
   - Índices de §10: `(company_id, captured_at desc)`, `cliente_rut`, `numero`, `conformidad_nivel`, índice único en `client_id` y en `companies.invite_code`, y un índice GIN de texto (`to_tsvector('spanish', coalesce(cliente_nombre,'') || ' ' || coalesce(local,'') || ' ' || coalesce(sello_texto,''))`) o `pg_trgm` si resulta más simple para búsqueda parcial. Documentá la elección en un comentario.
4. `drizzle-kit` para generar migraciones en `server/drizzle/`. Scripts: `npm run db:generate`, `npm run db:migrate`.
5. Tests con **PGlite** (`@electric-sql/pglite` + `drizzle-orm/pglite`): helper `createTestDb()` que aplica las migraciones en memoria. Un test que inserta una empresa, un usuario, una membresía y un escaneo, y lee el escaneo de vuelta.
6. Helper `effectiveValue(scan, key)` en `server/src/db/scans.ts`: devuelve `corrections[key]` si existe, si no `extracted[key]` (regla de lectura de §10), con test.

## Entregables

PR con config, app, esquema, migraciones, helper de test y tests.

## Criterios de aceptación

- `npm test` pasa usando PGlite (no requiere Postgres instalado).
- `GET /health` devuelve 200 (test con supertest).
- La migración inicial crea las 10 tablas con todos los índices.

## Fuera de alcance

Endpoints de negocio, seed (T1.2), almacenamiento (T1.5).
