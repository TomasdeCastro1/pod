# T0.1 · Prerrequisitos (tarea de Francisco)

**Fase:** 0 · **Quién:** 👤 Francisco · **Depende de:** nada · **Desbloquea:** todo el plan

Esta tarea no la puede hacer una sesión de Sonnet: son cuentas, pagos, fotos y decisiones.

## 1. Repositorio

- [ ] Crear un repositorio privado en GitHub (nombre sugerido: `comprobantes`).
- [ ] Conectarlo al proyecto POD en Claude (Configuración del proyecto → Repositorios) y al entorno donde vayan a correr las sesiones de Claude Code.
- [ ] Rama principal: `main`, con protección para que todo entre por PR.

## 2. Fotos de muestra

- [ ] Subir las 11 fotos reales a `samples/` con los nombres `01.jpg` … `11.jpg` según la tabla «Resultados esperados» de la sección 14 de la especificación.
- [ ] Si alguna foto tiene datos que no deberían estar en GitHub, el repo tiene que ser privado (lo es por defecto en el punto 1).

## 3. Cuentas y claves

| Servicio | Para qué | Dónde va la clave |
|---|---|---|
| Anthropic | Extracción con IA | `ANTHROPIC_API_KEY` en Replit Secrets **y** en los secrets del entorno de Claude Code (lo necesitan T1.9 y T7.1) |
| Replit | Hosting del backend, PostgreSQL, Object Storage | — |
| Resend | Envío de los códigos de login | `RESEND_API_KEY` en Replit Secrets; verificar un dominio remitente |
| Expo | EAS Build y Submit | `EXPO_TOKEN` en los secrets del entorno de Claude Code si querés que Sonnet lance builds |
| Apple Developer Program | App Store y TestFlight (USD 99/año) | — |
| Google Play Console | Google Play (USD 25, pago único) | — |

Generar además `JWT_SECRET`, `ADMIN_TOKEN` y `SIGNED_URL_SECRET` (cadenas aleatorias largas) y guardarlos en Replit Secrets.

## 4. Decisiones

- [ ] **Identificador de la app:** `uy.<empresa>.<app>` (ejemplo: `uy.puntosano.comprobantes`). No se puede cambiar después del primer build.
- [ ] **Nombre visible de la app** en las tiendas.
- [ ] **Dominio** para la API y las páginas legales (o usar el de Replit al principio).
- [ ] **Email y código fijo de la cuenta de revisión** (`REVIEW_EMAIL`, `REVIEW_CODE`).
- [ ] Revisar la tabla «Huecos de la especificación» del [README](../README.md#4-huecos-de-la-especificación-y-la-decisión-que-toma-el-plan) y aceptar o cambiar cada decisión.
